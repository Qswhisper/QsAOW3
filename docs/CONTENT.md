# 内容与原输入

## 当前输入来源与边界

启动 APK 提供原客户端和接入时保留的原输入：字典/初始配置、地图资源、原战役/合作开始对象、菜单缓存图。构建不会连接原服务器或批量生成缺失关卡。`data/assets-manifest.json` 仅记录这些输入的路径、大小和 SHA256，不含个人存档或 Android 偏好。

普通战役当前覆盖联盟 01–21、反抗 01–34。原 100 个普通章节仍有 45 个未接入；完整困难及其他独立合作/赛事输入也不齐。不同章节、军队布局和原脚本不能通过同图改名来补足。

## 路由

`content/campaign_routes.json` 每行指定：

- `faction`、`chapter`：稳定的本地阵营/生涯章节身份。
- `recorded`、`map`：原开始对象与真实地图身份。
- `previous`：同阵营前置章节，`-1` 为起点。
- `source`、`sha256`：`offline-campaign/<sha256>.ggs` 原输入；不再引用私人采集目录。
- `kind`：原输入来源类型；`presentation`、`growth` 指定已经实现的原变体投影/成长规则。

`data/mission-index.json` 保存路由校验所需的原任务身份字段。原早期 m 变体使用真实的原开始对象/地图/对白，再投影到稳定生涯序号；这与随意换一张地图不同。

合作目录独立于战役。当前已验证反抗任务 973 / 地图 558，玩家席位 1、AI 队友席位 3。新的合作席位/目标类型需要实现并验证共用规则，再放宽 `tools/content.py` 中的对应契约。

## 扩展流程

1. `python tools/content.py stage` 提取当前输入到 `.local/assets`。
2. 加入合法取得的原输入并核对真实地图、阵营、难度、席位、目标和上下文；剔除 profile、账号、会话和设备信息。
3. 将开始对象按 SHA256 存入 `offline-campaign`，补原任务元数据，编辑路由。目录中的前置必须完整、同阵营且无环。
4. `python tools/content.py rebuild` 更新二进制目录；同步输入校验清单后，用 `build.py --assets` 打包。
5. 做共用目录/目标机制检查和必要代表场景验收；缺失输入按具体内容记录，避免影响无关机制继续实现。

变更清单应说明玩家多了什么可玩的内容。目录项数量、截图数量或同关改名不能代替这一说明。

## 其他定义

已核实的合同、奖励、研究和英雄等定义多数以 `native/*_content.generated.h`、规则表或测试 fixture 提交。它们是当前可直接编译的输入。修改规则表时保持持久化身份/槽位，注明原定义与单机规则的区别，并补足相关解析、原价扣费和失败拒绝检查。
